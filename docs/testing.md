# پذیرش روی cPanel و کلاینت‌ها

وضعیت اولیه: تست cPanel واقعی و لینک کاربران هنوز انجام نشده است. این چک‌لیست را برای هر انتشار تکمیل کنید و نسخه پنل، PHP، هاست و کلاینت را ثبت کنید؛ توکن‌ها را ثبت عمومی نکنید.

| تست | Marzban | PasarGuard | Dual |
|---|---|---|---|
| دریافت لینک واقعی و مقایسه با upstream | ☐ | ☐ | ☐ |
| HTML صفحه ساب، لینک‌ها و منابع | ☐ | ☐ | ☐ |
| به‌روزرسانی در v2rayNG یا v2rayN | ☐ | ☐ | ☐ |
| فرمت در کلاینت Clash | ☐ | ☐ | ☐ |
| مصرف، حجم و انقضا از هدر | ☐ | ☐ | ☐ |
| query و suffix فرمت | ☐ | ☐ | ☐ |
| عدم دسترسی عمومی به config و key | ☐ | ☐ | ☐ |

در حالت مشترک، یک توکن واقعی از هر پنل و یک توکن ناموجود تست کنید. با لاگ آزمایشی upstream ثابت کنید پنل دوم فقط بعد از 404 درخواست دریافت می‌کند. پاسخ 200، 401، 403، 429، 500، TLS failure و timeout پنل اول نباید درخواست دوم ایجاد کنند. اگر توکن ناموجود در مرزبان غیر404 است، نصب مشترک را تأیید نکنید.

installer: کلید غلط، CSRF غلط، خلاصه قبل از ذخیره، config موجود و قفل نصب را تست کنید. بکاپ/rollback را نیز تمرین کنید. منابع خارجی صفحه روی شبکه ایران ممکن است مستقل از relay مسدود باشند.
