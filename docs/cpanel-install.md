# نصب در cPanel

## آماده‌سازی و بکاپ

از Document Root و فایل مخفی `.htaccess` و مقدار prefix فعلی هر پنل بکاپ بگیرید؛ بکاپ را خارج از پوشه عمومی نگه دارید. زیردامنه اختصاصی `sub.example.com` و SSL معتبر بسازید. از MultiPHP Manager یا Select PHP Version، نسخه 8.1+ و cURL را فعال کنید. PHP session باید کار کند.

## آپلود

ZIP مخزن را استخراج کنید. محتوای `src/` را مستقیماً در Document Root زیردامنه قرار دهید. پوشه `src` را به عنوان یک زیرپوشه آپلود نکنید. در Settings گزینه Show Hidden Files را بزنید تا `.htaccess` دیده شود.

فایل‌های اجرایی: `index.php` و `relay.php`؛ مسیرها و حفاظت دسترسی: `.htaccess`؛ نصب: `installer.php`؛ تنظیمات: `config.php` که پس از تأیید ساخته می‌شود. نمونه‌ها و مستندات خارج از Document Root هستند.

## نصب وب

`setup-key.example.php` را به `setup-key.php` کپی کنید و مقدار return آن را به کلید تصادفی اختصاصی حداقل ۲۴ کاراکتر تغییر دهید. کلید را فقط در فرم HTTPS وارد کنید، نه URL. برای تولید کلید با ترمینال: `openssl rand -hex 24`.

`https://sub.example.com/installer.php` را باز کنید. حالت را انتخاب کنید. دامنه عمومی بدون مسیر، آدرس پنل با مسیر اشتراک و بدون توکن وارد شود. پورت غیرپیش‌فرض را داخل URL بنویسید: `https://panel.example.com:8443/sub`.

نصب‌کننده اتصال TLS را با توکن تصادفی بررسی و خلاصه را نشان می‌دهد. بعد از تأیید `config.php` ایجاد می‌شود و نصب‌کننده قفل می‌شود. فایل‌های `installer.php`، `setup-key.php` و `install.lock` را حذف کنید. معمولاً مجوز پوشه 755 و فایل‌ها 644 مناسب است؛ فایل تنظیمات با 600 ایجاد می‌شود. اگر PHP جداگانه اجرا می‌شود و نمی‌تواند آن را بخواند، از پشتیبانی هاست درباره مجوز صحیح سؤال کنید؛ 777 نگذارید.

## نصب دستی

از `examples/` حالت دلخواه را به `config.php` کپی کنید، دامنه‌ها را تغییر دهید و installer را حذف کنید. نمونه config صرفاً آرایه PHP است؛ هیچ کد یا مقدار دریافتی از کاربر در آن اجرا نمی‌شود.

## تنظیم پنل و تست

[مرزبان](marzban.md)، [پاسارگارد](pasarguard.md) یا [هر دو](dual-panel.md) را دنبال کنید. پیش از تغییر prefix، دریافت لینک اصلی پنل را تأیید کنید. سپس لینک عمومی ساخته‌شده باید دقیقاً `https://sub.example.com/sub/TOKEN` باشد؛ `/sub/sub/` خطاست.

[چک‌لیست تست واقعی](testing.md) را تکمیل کنید. مسیر `config.php` و `setup-key.php` در مرورگر باید 403 بدهد. تست توسعه با PHP built-in server قواعد `.htaccess` را بررسی نمی‌کند.

## ویرایش و بازگشت

برای تغییر آدرس، ترتیب، زمان انتظار یا محدودیت پاسخ، `config.php` را در File Manager ویرایش کنید. نصب‌کننده برای ویرایش روزمره استفاده نمی‌شود. برای rollback، فایل‌های قدیمی و prefix قبلی پنل را از بکاپ برگردانید. حذف config برای نصب مجدد فقط هنگام نگهداری برنامه‌ریزی‌شده و پس از بکاپ مجاز است.
