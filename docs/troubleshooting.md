# رفع خطا

| مشکل | راه‌حل |
|---|---|
| 404 همه لینک‌ها | محل `.htaccess`، فعال بودن rewrite، Document Root و `/sub/TOKEN` را بررسی کنید |
| 404 یک کاربر | توکن، انقضا/حذف کاربر و مسیر اصلی پنل را بررسی کنید |
| 502 | از خود هاست DNS، اتصال خروجی به پورت، TLS و زمان انتظار را بررسی کنید |
| 503 | وجود/خوانایی `config.php`، صحت آرایه، PHP و cURL |
| 500 | Error Log هاست، syntax فایل تنظیمات و پشتیبانی `.htaccess`؛ اسرار لاگ را عمومی نکنید |
| گواهی SSL | نام دامنه، تاریخ، fullchain و CA bundle PHP؛ TLS verification را خاموش نکنید |
| نصب‌کننده قفل است | وجود config یعنی نصب کامل است؛ config را ویرایش کنید |
| صفحه ناقص | URL منابع قالب، لینک‌ها و API خارج از `/sub` پشتیبانی نشده‌اند |
| قالب نامناسب کلاینت | لینک را با User-Agent واقعی کلاینت تست و با پنل اصلی مقایسه کنید |
| خطای Redirect | URL نهایی HTTPS و مسیر صحیح را در config بگذارید |

برای پورت خروجی مسدود از پشتیبانی هاست بخواهید دسترسی به مقصد/پورت مشخص را باز کند یا پنل را پشت HTTPS روی 443 قرار دهید. قطع مرزبان در حالت مشترک باعث fallback نمی‌شود.

از خود هاست لینک را با توکن آزمایشی غیرحساس بررسی کنید:

```bash
curl --connect-timeout 5 --max-time 20 -i https://panel.example.com/sub/NONEXISTENT_TEST_TOKEN
```

از `-k` استفاده نکنید. اطلاعات توکن کاربران، config و خروجی اشتراک را در Issue عمومی نگذارید. واسط لاگ توکن تولید نمی‌کند، ولی لاگ وب‌سرور هاست ممکن است مسیر کامل درخواست را ثبت کند؛ نگهداری و دسترسی آن را در تنظیمات هاست کنترل کنید.
